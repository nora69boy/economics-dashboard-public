# Publication rights registry and migration

This is a public-safe policy summary, not legal advice or a grant of rights.
The initial 40 entries are all UNKNOWN. No licence was inferred from a source
URL, government hosting, the earlier publication, or a passing CI run.
WTI remains UNKNOWN: EIA's source notes identify Refinitiv (LSEG), and EIA's
general reuse notice has a protected-material exception. VIX has no values
and is not included in the migration exemption.

## Files and integration

- `registry.json`: one entry per market instrument, macro primary/auxiliary
  series, financial dataset, calendar family, or existing research payload.
- `migration-baseline.json`: the finite scope already published from source
  commit `7460524c290b22c8c6f6b1c6bf64cbefeb95549f`. Its canonical JSON SHA-256
  is pinned in `scripts/publication_rights.py`; it is never auto-generated by CI.
- `scripts/check_release.py` invokes the rights gate on the actual validated
  six-file payload before `.pages-build` is prepared or an artifact is uploaded.
  Direct calls to `validate()` also enforce it. CI runs `tests/test_rights.py`.
- Neither this directory nor the rights report is added to the Pages payload.
  The repository and PR source archive are themselves public: do not store
  contracts, personal details, authentication material, or confidential terms.

## Schema and purpose decisions

`status` is APPROVED, CONDITIONAL, UNKNOWN, PROHIBITED, EXPIRED, or REVOKED.
Each purpose field (`access`, `automated_retrieval`, `storage`, `transformation`,
`display`, `redistribution`, `commercial_use`, `caching`, `ai_processing`) is
ALLOWED, DENIED, or UNKNOWN. These are independent of the overall status.
`source_url` and `terms_url` are arrays, since one dataset can have several
sources. A missing terms review is represented by an empty array, not a guessed
terms URL. `reviewed_at` is null until an actual rights review is recorded.

Publication requires ALLOWED storage, transformation, display, redistribution,
and caching, matching sources, fields and public targets, and valid retention.
This gate does not enable acquisition, AI processing or commercial use; those
decisions are recorded but would need separate enforcement before enabling
those activities. Existing ETL and browser behavior are unchanged.

APPROVED and CONDITIONAL require a reviewed date, terms URL, public evidence
reference with terms SHA-256 and product-owner role, effective dates, review
deadline, and WHILE_VALID retention. This first version requires an explicit
valid-until date even if a licence otherwise permits indefinite use. Dates are
inclusive and evaluated using the runner date, never the payload retrieval date.
An elapsed review deadline blocks approved/conditional publication.
`max_age_days` limits the oldest published observation, including revisions;
unknown observation dates cannot satisfy a finite retention limit.

CONDITIONAL also requires at least one executable condition. The only supported
condition is `{"type":"attribution","text":"...","targets":["index.html"]}`:
the literal acknowledgement must occur in every named final payload after HTML
entity decoding. Free-form promises or an unchecked boolean cannot satisfy it.
This is a payload-content check, not proof of visible rendering or legal
sufficiency; the owner must choose a condition suitable for the actual licence.
A non-null top-level attribution is required in all of that dataset's public
targets. Unknown condition types fail closed. Unsupported licence conditions
require a separately reviewed implementation, not a generic override.

## Migration, explicitly requested for this change

The owner requested continued operation for existing UNKNOWN datasets while
rights review is pending. This is a temporary operational exception, not an
APPROVED or CONDITIONAL licence decision and not a D1 acceptance pass.

- Exactly 39 already-published entries may produce `EXISTING_UNKNOWN` warnings
  with `migration_status: PENDING_RIGHTS_REVIEW`.
- The baseline binds each ID to its sources, fields and public targets. Adding
  an entry to the registry cannot create a migration exemption.
- Fixed market, financial, calendar and research snapshots also bind canonical
  content hashes. Added observations or changed values require rights review.
- The 12 existing non-VIX macro primary/auxiliary series may continue the same
  existing periodic refresh, including revisions, within their existing source,
  field and target scope. New observations in those existing series remain
  migration warnings. New series, auxiliary series, providers and uses do not.
- VIX is registered UNKNOWN but unpublished; publishing values would block.
- PROHIBITED, EXPIRED, REVOKED, elapsed validity, explicit purpose denial and
  retention restrictions override migration, including for existing data.
- No unapproved migration expiry date or schedule change is introduced.
  Exit requires public-safe rights evidence and owner review, or a separately
  approved removal. Lack of an automatic sunset remains an operational risk.

Static HTML is also pinned after the two macro payloads and the exactly checked
macro fallback are replaced with markers. This prevents new HTML-only values
from bypassing the JSON inventory. A future UI/template change therefore needs
review of the HTML binding even when the dataset list is unchanged. It is not
silently enrolled by the build. The baseline digest is a review tripwire, not a
signature against an actor who can change both the code and policy.

## Reports, checks and remaining limits

`python3 scripts/check_release.py --check-history --build` emits a deterministic
`RIGHTS_REPORT` JSON line with all six registry status counts, published and
unpublished counts, fixed reason codes and validated dataset IDs. Migration emits
a visible CI warning. Blocked publication exits nonzero before artifact creation.
No provider values, URLs, evidence text, private paths or raw exceptions are
included in rights reports. Missing/invalid policy emits a fixed error rather
than inventing counts. Run `python3 -m unittest discover -s tests -p test_rights.py -v`.

Initial counts: APPROVED 0, CONDITIONAL 0, UNKNOWN 40, PROHIBITED 0, EXPIRED 0,
REVOKED 0; 39 published migration entries and 1 unpublished VIX entry.
Counts are registry entries, not the 7-macro or 20-market coverage denominators.

The gate does not verify the truth of a human-supplied licence record, contact a
provider, detect a revocation before it is recorded, remove an already deployed
artifact, or replace review of public commits. GitHub permissions, human release
approval, source review and an approved withdrawal process remain necessary.
No change to production, the update schedule, privacy/CSP checks, browser tests,
data retrieval, analytics, or UI is part of this implementation.
